# ERC-2612

在传统 ERC-20 中，用户想让某个合约（比如 DEX）使用自己的 token，流程是：

1. `approve(spender, amount)`（用户发交易，付 gas）
2. `transferFrom(from, to, amount)`（合约再调用）

👉 问题：

- 用户必须持有 ETH 才能授权（gas）
- UX 很差（2 笔交易）
- 无法做到“无 gas 授权”

# ERC-2612 的核心思想

👉 **用签名代替链上授权交易**

用户不需要发送 `approve` 交易，而是：

1. 在链下签名（免费）
2. 把签名交给别人（比如 DApp / Relayer）
3. 对方帮你提交链上交易

这就是：

> **Gasless Approval（无 gas 授权）**

# ERC-2612 核心接口

ERC-2612 增加了 3 个关键内容：

### 1️⃣ permit()

```
function permit(
    address owner,
    address spender,
    uint256 value,
    uint256 deadline,
    uint8 v,
    bytes32 r,
    bytes32 s
) external;
```

作用：
 👉 用签名完成 approve

------

### 2️⃣ nonces()

```
function nonces(address owner) external view returns (uint256);
```

👉 防止签名被重复使用（重放攻击）

------

### 3️⃣ DOMAIN_SEPARATOR()

```
function DOMAIN_SEPARATOR() external view returns (bytes32);
```

👉 用于 EIP-712 签名域隔离

# 工作流程（非常关键）

完整流程如下：

------

## Step 1：用户签名（链下）

用户签一个结构化数据（EIP-712）：

```
Permit(
  owner,
  spender,
  value,
  nonce,
  deadline
)
```

------

## Step 2：Relayer / DApp 提交

任何人都可以调用：

```
permit(...)
```

并附上签名 `(v, r, s)`

------

## Step 3：合约验证签名

合约内部会：

1. 计算 hash（EIP-712）
2. 用 `ecrecover` 恢复 signer
3. 检查：
   - signer == owner
   - nonce 正确
   - 未过期

------

## Step 4：更新 allowance

```
allowance[owner][spender] = value;
```

👉 等价于 approve！

------

# 五、签名结构（EIP-712）

ERC-2612 依赖 EIP-712

核心 hash：

```
keccak256(
  abi.encode(
    PERMIT_TYPEHASH,
    owner,
    spender,
    value,
    nonce,
    deadline
  )
)
```

再结合：

```
keccak256(
  "\x19\x01",
  DOMAIN_SEPARATOR,
  structHash
)
```
