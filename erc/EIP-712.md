# EIP-712

在 EIP-712 之前，签名主要有两种：

### 1️⃣ `eth_sign`

```
0x8f3a92ab...（一坨 hex）
```

❌ 用户完全看不懂 → 极易被钓鱼

------

### 2️⃣ `personal_sign`

```
"Send 1 ETH to Bob"
```

✔ 可读
 ❌ 不结构化，难以验证

####  EIP-712 的目标是：

| 能力     | 是否支持 |
| -------- | -------- |
| 人类可读 | ✅        |
| 结构化   | ✅        |
| 可验证   | ✅        |
| 防钓鱼   | ✅        |

# EIP-712 三大核心结构

------

## 1️⃣ Domain（域隔离）

```
{
  "name": "MyDApp",
  "version": "1",
  "chainId": 1,
  "verifyingContract": "0x..."
}
```

作用：

👉 防止签名被跨场景复用

例如：

- A DApp 的签名 ❌ 不能在 B DApp 用
- 主网签名 ❌ 不能在测试网用

------

## 2️⃣ Types（数据结构）

```
{
  "Permit": [
    {"name": "owner", "type": "address"},
    {"name": "spender", "type": "address"},
    {"name": "value", "type": "uint256"}
  ]
}
```

👉 类似 Solidity struct

------

## 3️⃣ Message（具体数据）

```
{
  "owner": "0xabc...",
  "spender": "0xdef...",
  "value": "1000000000000000000"
}
```

# 完整签名结构

最终签的是：

```
EIP712Hash = keccak256(
  "\x19\x01" ||
  DOMAIN_SEPARATOR ||
  structHash
)
```

------

👉 核心公式（最重要）：

```
hash = keccak256(
  "\x19\x01" + domainSeparator + structHash
)
```

# 关键安全点

------

## ⚠️ 1. Domain 必须唯一

否则可能：

👉 跨合约重放攻击

------

## ⚠️ 2. chainId 必须包含

防止：

👉 跨链重放

------

## ⚠️ 3. nonce 必须存在

防止：

👉 同一签名被无限使用

------

## ⚠️ 4. 前端展示必须清晰

否则用户可能签：

👉 “无限授权” 😅
