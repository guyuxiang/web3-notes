### EIP-1193签名相关

#### 背景

`Web3.js`认为用户会在本地部署以太坊节点，私钥和网络连接状态由这个节点管理（实际并不是这样）

在`ethers.js`中，实现了读写分离,  是目前更流行, 更安全的连接以太坊方式

1. `Provider`提供器类管理网络连接状态, 单纯使用Provider是只读的
2. `Signer`签名者类管理密钥，安全且灵活，`Signer`签名者类是以太坊账户的抽象，可用于对消息和交易进行签名
   `Wallet`钱包类继承了Signer类(`Signer`类是抽象类，不能直接实例化)，并且开发者可以像包含私钥的外部拥有帐户（EOA）一样，用它对交易和消息进行签名。

过去由于不同钱包提供的接口方法各不相同, dapp需要对接不同钱包的api非常麻烦, 比如要签名时, 需要针对不同钱包写多套签名过程

因此, **EIP-1193**标准化了钱包Provider API, 使得dapp可以操作不同的钱包, 对钱包抽象化



签名相关接口标准

```javascript
// 返回账户地址
abstract getAddress(): Promise<string>

// 对字符串类型消息进行签名
abstract signMessage(message: Bytes | string): Promise<string>;

// 对交易类型进行签名并返回序列化后的签名结果
abstract signTransaction(transaction: Deferrable<TransactionRequest>): Promise<string>;

// 连接指定的provider
abstract connect(provider: Provider): Signer;
```



```javascript
// ethers.js 6.1.0
const provider = new ethers.BrowserProvider(safeAuthPack.getProvider() as Eip1193Provider)
const signer = provider.getSigner()
```
