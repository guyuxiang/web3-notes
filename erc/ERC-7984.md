# ERC-7984

ERC-7984 的设计目标是：**继续保留账户模型（account-based accounting）**，但把**余额和转账金额保密**。EIP 原文就把它定义为：在保持账户式记账模型的同时，维持转账金额和余额的机密性。

## 核心抽象：不是金额，而是 `bytes32` 指针

ERC-7984 最核心的概念是 **pointer-based amounts**。

EIP 规定，标准里的金额都不是直接传 `uint256`，而是传一个 **`bytes32` 指针**；这个指针指向“别处”的保密数据，可能存链上，也可能存链下，具体解析方式由实现决定。也就是说，**标准只规范接口，不强行规定底层密码学**。

### ERC-7984 的定义

- `confidentialBalanceOf(address) -> bytes32`
- `confidentialTotalSupply() -> bytes32`
- `confidentialTransfer(...) -> bytes32`
- 没有按额度的 `approve/allowance`
- 改成 **operator 模型**



## 事件

ERC-7984 不是 `Transfer(address,address,uint256)`，而是：

- `ConfidentialTransfer(address from, address to, bytes32 amount)`
- `OperatorSet(address holder, address operator, uint48 until)`
- `AmountDisclosed(bytes32 handle, uint256 amount)`（可选/建议触发）







在 OpenZeppelin 的 Zama 版实现里，接口会进一步具体化成 `euint64`、`externalEuint64` 之类 FHE 类型，也会配 `inputProof`

OpenZeppelin 已经在其 confidential contracts 库里提供了 ERC7984 相关实现，并明确写明这些实现**利用 Zama fhEVM coprocessor**，金额在链上表现为“指向协处理器中值的 ciphertext handles / pointers”。

https://docs.openzeppelin.com/confidential-contracts/api/token?utm_source=chatgpt.com



## ERC-20 主稳定币 + ERC-7984 包装层

这是我更推荐的。

OpenZeppelin 已提供 `ERC7984ERC20Wrapper`，用于把 ERC-20 包装成 confidential ERC-7984 token，并支持固定比例双向转换。
