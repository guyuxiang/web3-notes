## 多签方案

### MPC钱包

使用市面上主流的MPC产品或者组件

**付费：**

**Fireblocks：**全球最大的机构级MPC托管平台，客户包括Coinbase、eToro等。

- MPC-CMP协议：支持多方协作签名，兼容硬件隔离（HSM）。
- 合规工具：内置Travel Rule、交易审批流、审计日志。
- 基础版每年4,200 USD费用https://www.fireblocks.com/pricing/

![image-20250306162548585](C:\Users\顾宇翔\AppData\Roaming\Typora\typora-user-images\image-20250306162548585.png)



**免费：**

**Safeheron：**开源的MPC算法实现，包括密钥生成、签名等，支持企业级安全需求

- 支持算法：ECDSA、EdDSA、SM2（国密算法）。
- 白盒审计：代码透明，可通过社区或第三方审计。
- 自托管：部署在自有服务器，无需依赖第三方服务。

**tss-lib **：由Binance发起并维护的开源库，专注于阈值签名（TSS）协议，支持ECDSA和EdDSA算法，适用于分布式密钥管理和签名。

- 成熟协议：已集成至Trust Wallet等知名产品。

- 跨平台：Go语言实现，可嵌入多种系统。

  

### **智能合约钱包**

Safe多签钱包是以太坊最流行的多签钱包，Safe 广泛应用于个人资产管理、DAO 治理、企业财务等领域，管理近千亿美元资产，合约经过审计和实战测试，支持多链（以太坊，BSC，Polygon等）， 已融资1亿美金

以 Safe 钱包（原名 Gnoiss Safe）为例，可自定义功能，例如：

- 多重签名逻辑（安全）：实现 2/3 和 3/5 等多重签名逻辑
- 自定义签名密码学算法，用户不需要备份助记词 / 私钥或者感知到它们的存在
- 动态管理多签，可以更新多签名单和阈值
- 基于角色的权限管理，可以为密钥设置权重和角色。不同的角色可以执行不同的操作。每个角色也有相应的阈值。如果超过此阈值，可以执行相应角色的权限
- 为不同级别的支出设置不同的审批流程，允许分层管理，设置小额支出而无需其他所有者同意的预算
- 转账黑名单和白名单校验
- 支出限额
- 利用 email 的密码学证明（DKIM Signature）或者电子护照等生活中常见的密码学工具来增强社交恢复方案的实用性
- 在完全控制钱包的同时，用户可以批准公用事业和订阅账单的自动化支付，在特定日期安排和/或自动交易。
- 基于时间条件触发
- 基于预言机条件触发
- 生成会话密钥重复交易



## 资金管理机制

### 金库合约方案

ERC-4626合约（金库标准），Aave V3、Balancer、Yearn Finance协议使用该标准质押用户代币

- 标准化定义的 `deposit()`（存款）、`mint()`（铸造凭证）、`withdraw()`（取款）、`redeem()`（赎回）等方法
- 提供质押凭证代币和收益计算方法
- 自定义取款条件，可接入预言机条件和定时触发取款



### **分层冷热钱包体系**

**热钱包**：始终连接互联网的加密货币钱包，用于日常交易和快速访问资金。

**冷钱包**：完全离线存储私钥的加密货币钱包，隔绝互联网以提升安全性。

**分层体系：**

- 冷钱包：90%以上资产存放在完全离线的冷钱包中，私钥存储在符合**FIPS 140-2 Level 3**标准的硬件安全模块（HSM） 中或者 **EAL5+认证** 的芯片级安全元件中，使用多重签名（Multi-sig） 技术，每笔交易需多个授权人审批，一般用于大额转账。
- 热钱包：保留10%资产用于日常提款，使用单签或者多签或者自动签名



**存取与操作流程**
资产存入：

1. 为客户生成专属热钱包存款地址。
2. 资产先进入热钱包，根据资金量是否达到阈值转入冷钱包。

资产提取：

1. 客户提交提款请求，需通过自动或人工审核。
2. 小资金量直接操作热钱包转账

3. 大额资金使用冷钱包配合多签后转账



**优点**

风险控制：通过多层级管理分散风险，减少单次安全事件可能导致的财务损失，还可以降低内部操作风险。

成本优化：不同层级由不同团队管理（如热钱包由运营团队操作，冷钱包由高管或董事会控制），可针对不同层级配置资源，避免过度投入。





### 方案设计

私钥存储方案选择

- [ ] ​	软件钱包：安全性较差
- [ ] ​	HSM：安全性强，云服务贵
- [x] ​	硬件钱包：安全性强，价格合理

多签方案选择

- [ ] ​	第三方机构级MPC钱包：服务费用昂贵
- [ ] ​	开源MPC算法库：需要开发前后端进行集成，且需要自行部署和运维
- [x]  	Safe智能合约钱包：开源可靠，接口成熟，使用广泛

资金管理机制选择

- [ ] ​	金库合约：虽然对金融活动的可拓展性强，且目前只需要基本质押功能，不涉及对质押资金进行理财等收益行为，因此不多引入安全风险

- [x] ​	分层冷热钱包体系：分层的资金管理策略隔离风险、平衡安全与效率，是目前主流加密货币交易所的数字资产托管的核心安全架构

  

因此使用： Safe智能合约钱包 + 硬件钱包 + 分层冷热钱包体系的组合



**前端集成**

- `@safe-global/api-kit`：与Safe交易中继服务交互，进行多签协作，提交交易
- `@safe-global/protocol-kit`：与Safe智能合约账户交互，如创建钱包、签名阈值
- `@ledgerhq/hw-transport-webusb、@ledgerhq/hw-app-eth`：硬件钱包库，用于调取Ledger硬件钱包进行签名



**后端签名机服务**（作为多签的一个成员）

- 独立对交易数据正确性进行自动化验证
- 独立对转账地址进行白名单验证（防止黑客篡改）
- 对大额转账进行时间锁，涉及冷钱包的大额资金需根据币种和风控级别设置时间锁
- KYC/AML



**分层冷热钱包体系场景案例：**

假设目前有2个运营、一个高管、一台签名机（自动签名机负责对交易数据正确性验证和监管，确认无误后签名）

热钱包层
    [总资金量10%，多钱包集群，小资金量转账]
    [2/3多签（Safe智能合约钱包账户）+ 硬件钱包（如Ledger）]
    [签名角色：运营  + 自动签名机（必须）]

​    [热钱包资金达到阈值时，通知进行资金归集到冷钱包]

冷钱包层
    [总资金量90%，单一钱包，大资金量转账]
    [3/4多签（Safe智能合约钱包账户）+ 硬件钱包（如Ledger）]
    [签名角色：运营 + 高管（必须）  + 自动签名机（必须）]
