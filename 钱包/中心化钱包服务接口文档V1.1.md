# 中心化钱包服务接口文档V1.1

## 1. 基本说明

### 1.1 适用范围

本文档用于交易所/平台与中心化钱包服务之间的接口对接，覆盖以下能力：

1. 钱包信息查询
2. 钱包转入通知回调
3. 钱包转出
4. 钱包转出结果通知回调
5. 转入转出交易结果查询
6. 转入转出历史交易查询

------

## 2. 接口约定

### 2.1 通信协议

- 协议：HTTPS
- 数据格式：`application/json`
- 字符编码：`UTF-8`

### 2.2 通用请求头

```
Content-Type: application/json
X-App-Id: your_app_id
X-Timestamp: 1710000000000
```



### HMAC 验签

增加 `X-Signature` 字段。对所有主动请求和回调都进行签名校验。



**签名算法**

签名算法：

```
Ed25519
```

签名编码：

```
Base64(signature)
```

Body 摘要算法：

```
SHA-256
```



**待签名字符串**

客户端按如下顺序拼接字符串：

```
HTTP_METHOD + "\n" +
REQUEST_PATH + "\n" +
QUERY_STRING + "\n" +
BODY_SHA256 + "\n" +
X_TIMESTAMP
```

说明：

- `HTTP_METHOD`：如 `GET`、`POST`
- `REQUEST_PATH`：请求路径，如 `/api/v1/orders`
- `QUERY_STRING`：URL 中 `?` 后的原始字符串，无则为空
- `BODY_SHA256`：请求体Body的 SHA256 十六进制值
- `X_TIMESTAMP`：请求头时间戳



**Body 摘要**

请求体使用原始 JSON 字符串计算：

```
BODY_SHA256 = SHA256(body_raw)
```

空 body：

```
BODY_SHA256 = SHA256("")
```



**签名生成**

客户端使用私钥对待签名字符串签名：

```
signature = Ed25519.Sign(private_key, signing_string)
```

然后：

```
X-Signature = Base64(signature)
```



**验签流程**

服务端收到请求后：

1. 根据 `X-API-Key` 获取调用方公钥
2. 检查 `X-Timestamp` 是否在允许时间范围（默认 ±300 秒）
3. 按规则重新构造待签名字符串
4. 使用公钥验证 `X-Signature`
5. 验签通过后才执行业务逻辑

 **示例**

请求：

```
POST /api/v1/orders?symbol=BTCUSDT HTTP/1.1
Host: api.example.com
Content-Type: application/json
X-App-Id: your_app_id
X-API-Key: sk-23f556
X-Timestamp: 1710000000
X-Signature: Base64SignatureHere
```

Body：

```
{"side":"BUY","amount":"1.5"}
```

待签名字符串：

```
POST
/api/v1/orders
symbol=BTCUSDT
<body_sha256>
1710000000
```

## 3. 数据字典

### 3.1 网络标识

建议统一使用链标准简称：

| network  | 说明            |
| -------- | --------------- |
| ethereum | Ethereum        |
| bsc      | BNB Smart Chain |
| polygon  | Polygon         |
| tron     | Tron            |
| solana   | Solana          |
| bitcoin  | Bitcoin         |

### 3.2 代币地址说明

- 查询或转账原生代币时，`tokenAddress` 传字符串 `"NATIVE"` 
- ERC20 / TRC20 / SPL Token 等非原生代币，tokenAddress 为具体合约地址 / mint 地址

### 3.3 交易方向

| direction | 含义 |
| --------- | ---- |
| IN        | 转入 |
| OUT       | 转出 |

### 3.4 交易状态

#### 转出交易

```
PROCESSING -> SUCCESS
            └-> FAIL
```

| status     | 含义   |
| ---------- | ------ |
| PROCESSING | 处理中 |
| SUCCESS    | 成功   |
| FAIL       | 失败   |

#### 转入交易

```
SUCCESS -> FAIL
```

| status  | 含义              |
| ------- | ----------------- |
| SUCCESS | 已到账            |
| FAIL    | 回滚失败/交易失效 |



### 3.5 幂等设计

#### 3.5.1 主动请求幂等

以下接口建议做幂等：

- 钱包转出接口：按 `requestNo`
- 回调通知：按 `notifyId`

#### 3.5.2 幂等规则

- 相同 `requestNo` 的转出请求，只能生成一个 `transactionNo`
- 相同 `notifyId` 的回调通知，业务方只处理一次

## 4.1 钱包信息查询

### 接口说明

根据钱包编号，查询钱包基础信息，以及各网络下的钱包地址、原生代币余额和支持的代币余额。

### 请求地址

```
POST /api/v1/wallet/info/query
```

### 请求参数

| 字段     | 类型   | 必填 | 说明     |
| -------- | ------ | ---- | -------- |
| walletNo | string | 是   | 钱包编号 |

### 请求示例

```
{
  "walletNo": "W202603100001"
}
```

### 响应参数

| 字段     | 类型   | 说明         |
| -------- | ------ | ------------ |
| walletNo | string | 钱包编号     |
| tokens   | array  | 代币余额列表 |

`tokens` 字段说明：

| 字段        | 类型   | 说明     |
| ----------- | ------ | -------- |
| tokenSymbol | string | 代币符号 |
| balance     | string | 余额     |

### 响应示例

```
{
  "code": "0",
  "message": "success",
  "data": {
    "walletNo": "W202603100001",
    "tokens": [
        {
        "tokenSymbol": "USDC",
        "balance": "1023.560000"
        },
        {
        "tokenSymbol": "USDT",
        "balance": "500.000000"
        }
    ]
  }
}
```

## 4.2 回调接口：钱包转入通知

### 接口说明

钱包服务检测到指定钱包有转入交易时，主动回调业务方通知。

### 回调地址

由业务方提供，例如：

```
POST /callback/wallet/deposit
```

### 请求参数

| 字段          | 类型    | 必填 | 说明                     |
| ------------- | ------- | ---- | ------------------------ |
| notifyId      | string  | 是   | 通知唯一编号             |
| transactionNo | string  | 是   | 平台交易编号             |
| walletNo      | string  | 是   | 钱包编号                 |
| network       | string  | 是   | 网络                     |
| address       | string  | 是   | 收款地址                 |
| fromAddress   | string  | 否   | 付款地址                 |
| tokenAddress  | string  | 否   | 代币地址，原生币为空     |
| tokenSymbol   | string  | 是   | 币种符号                 |
| amount        | string  | 是   | 转入数量                 |
| txHash        | string  | 是   | 链上交易哈希             |
| blockHeight   | string  | 否   | 区块高度                 |
| confirmations | integer | 否   | 当前确认数               |
| status        | string  | 是   | 交易状态：SUCCESS / FAIL |
| txTime        | long    | 是   | 链上交易时间戳，毫秒     |
| notifyTime    | long    | 是   | 回调通知时间戳，毫秒     |

### 请求示例

```
{
  "notifyId": "N202603100001",
  "transactionNo": "T202603100001",
  "walletNo": "W202603100001",
  "network": "ethereum",
  "address": "0x8A1b2c3D4e5F678901234567890123456789ABCD",
  "fromAddress": "0x1234567890abcdef1234567890abcdef12345678",
  "tokenAddress": "0xdAC17F958D2ee523a2206206994597C13D831ec7",
  "tokenSymbol": "USDT",
  "amount": "100.000000",
  "txHash": "0xabc123def4567890",
  "blockHeight": "21900001",
  "confirmations": 12,
  "status": "SUCCESS",
  "txTime": 1760000000000,
  "notifyTime": 1760000005000
}
```

### 回调响应

业务方需返回：

```
{
  "code": "0",
  "message": "success"
}
```

### 说明

- 若业务方返回非 `0`，钱包服务可进行重试
- 建议重试策略：1min、5min、15min、30min、1h，最多 6 次
- `notifyId` 用于幂等处理

## 4.3 钱包转出接口

### 接口说明

发起钱包转出请求，返回平台交易编号。

### 请求地址

```
POST /api/v1/wallet/transfer/out
```

### 请求参数

| 字段        | 类型   | 必填 | 说明                 |
| ----------- | ------ | ---- | -------------------- |
| requestNo   | string | 是   | 请求唯一编号，幂等键 |
| walletNo    | string | 是   | 钱包编号             |
| network     | string | 是   | 网络                 |
| toAddress   | string | 是   | 接收地址             |
| tokenSymbol | string | 否   | 币种符号             |
| amount      | string | 是   | 转出数量             |

### 请求示例

```
{
  "requestNo": "REQ202603100001",
  "walletNo": "W202603100001",
  "network": "ETH",
  "toAddress": "0x9999999999999999999999999999999999999999",
  "tokenAddress": "0xdAC17F958D2ee523a2206206994597C13D831ec7",
  "amount": "25.500000"
}
```

### 响应参数

| 字段          | 类型   | 说明         |
| ------------- | ------ | ------------ |
| transactionNo | string | 平台交易编号 |
| requestNo     | string | 原请求号     |

### 响应示例

```
{
  "code": "0",
  "message": "success",
  "data": {
    "transactionNo": "T202603100002",
    "requestNo": "REQ202603100001"
  }
}
```

### 说明

- `requestNo` 必须全局唯一
- 同一个 `requestNo` 重复请求，必须返回同一个 `transactionNo`
- 钱包服务应完成地址校验、余额校验、币种校验

## 4.4 回调接口：转出交易结果通知

### 接口说明

钱包服务在转出交易状态变化时，主动通知业务方。

只包括通过服务调用的转出交易，不包括其他渠道使用区块链网络的转出。

### 回调地址

```
POST /callback/wallet/transfer/out/result
```

### 请求参数

| 字段          | 类型   | 必填 | 说明                     |
| ------------- | ------ | ---- | ------------------------ |
| notifyId      | string | 是   | 通知唯一编号             |
| transactionNo | string | 是   | 平台交易编号(由服务生成) |
| requestNo     | string | 否   | 原请求号                 |
| walletNo      | string | 是   | 钱包编号                 |
| network       | string | 是   | 网络                     |
| toAddress     | string | 是   | 接收地址                 |
| tokenAddress  | string | 否   | 代币地址                 |
| tokenSymbol   | string | 是   | 币种符号                 |
| amount        | string | 是   | 转出数量                 |
| fee           | string | 否   | 手续费                   |
| txHash        | string | 否   | 链上交易哈希             |
| status        | string | 是   | PROCESSING/SUCCESS/FAIL  |
| failReason    | string | 否   | 失败原因                 |
| txTime        | long   | 否   | 交易上链时间戳，毫秒     |
| notifyTime    | long   | 是   | 通知时间戳，毫秒         |

### 请求示例

```
{
  "notifyId": "N202603100002",
  "transactionNo": "T202603100002",
  "requestNo": "REQ202603100001",
  "walletNo": "W202603100001",

  "failReason": "",

```

  "message": "success"
}

## 4.7 转入转出历史交易查询

### 接口说明

按时间戳分页查询历史交易，可筛选转入或转出。

### 请求地址

```
POST /api/v1/wallet/transaction/history/query
```

### 请求参数

| 字段      | 类型    | 必填 | 说明                                                         |
| --------- | ------- | ---- | ------------------------------------------------------------ |
| walletNo  | string  | 是   | 钱包编号                                                     |
| direction | string  | 否   | IN / OUT，不传则全部                                         |
| startTime | long    | 否   | 开始时间戳，毫秒                                             |
| endTime   | long    | 否   | 结束时间戳，毫秒                                             |
| pageSize  | integer | 是   | 每页条数，建议不超过 100                                     |
| cursor    | long    | 否   | 游标时间戳，首次为空，后续传上一页最后一条记录的 `createdTime` 或 `nextCursor` |

时间戳游标分页比页码分页更适合交易流水，原因是：

- 数据持续新增时不容易漏数或重复
- 适合大表和索引优化
- 更适合链上交易流水场景

### 分页规则

采用**时间戳游标分页**，按 `createdTime` 倒序。

首次请求：

- `cursor` 为空

下一页请求：

- 使用上次返回的 `nextCursor`

### 请求示例

```
{
  "walletNo": "W202603100001",
  "direction": "OUT",
  "startTime": 1759990000000,
  "endTime": 1760090000000,
  "pageSize": 20,
  "cursor": 1760090000000
}
```

### 响应参数

| 字段       | 类型  | 说明                           |
| ---------- | ----- | ------------------------------ |
| items      | array | 历史交易列表                   |
| nextCursor | long  | 下一页游标，无更多数据时返回 0 |

`items` 字段说明：

| 字段          | 类型   | 说明         |
| ------------- | ------ | ------------ |
| transactionNo | string | 平台交易编号 |
| direction     | string | IN / OUT     |
| walletNo      | string | 钱包编号     |
| network       | string | 网络         |
| fromAddress   | string | 来源地址     |
| toAddress     | string | 目标地址     |
| tokenAddress  | string | 代币地址     |
| tokenSymbol   | string | 币种符号     |
| amount        | string | 数量         |
| fee           | string | 手续费       |
