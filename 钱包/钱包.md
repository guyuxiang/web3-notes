# Web3 钱包需求设计文档

## 一、总体目标

设计并实现一个支持多链、多类型账户、多签名方式和多钱包管理的 Web3 钱包系统。

## 二、核心需求

### 1. 多链支持 (Multi-Chain)

支持以下链类型：

- EVM 类链 (Ethereum, BSC, Polygon, Arbitrum, Base, etc.)
- Solana
- Aptos
- XRPL (Ripple)
- Tron
- Doge/BTC

每条链需支持：

- 地址生成/校验
- 交易构造 + 签名 + 广播
- 签名类型选择 (Tx, TypedData, etc.)

### 2. 多类型钱包支持 (Multi-Type Accounts)

支持如下钱包类型：

- 生成或导入
  - Mnemonic / 私钥
  - 自研MPC
  - 第三方MPC：COBE/cloudKMS
  - 第三方托管钱包
  - 硬件钱包 (Ledger, Trezor, Keystone)
  - 智能合约钱包（ERC-4337 、EIP-7702、Safe）
  - 第三方钱包（metamask、okx wallet）

账户需支持:

- 地址获取
- 签名功能
- 其他操作

### 3. 多钱包管理 (Multi-Wallet Management)

支持同一用户下创建和管理多个钱包，包括不同链和类型的钱包

需添加:

- 创建/导入钱包
- 钱包删除/隐藏
- 分类标签（如「主钱包」、「存款钱包」、「质押钱包」）
- 切换当前操作钱包

每个钱包需显示：

- 钱包名称
- 钱包连接状态
- 钱包类型
- 链类型（MultiChain/EVM/XRPL...）
- 地址
- 资产总览（余额/NFT等）
- 交易
- 支持 ENS

### 4. 多签名方式支持 (Multi-Signature Methods)

KMS支持如下签名方式：

- 传统交易签名 (raw tx, 通过 keccak256 hash)
- TypedData / EIP-712 签名 (Dapp 用于授权或类声明操作)
- MPC 签名 (Shamir's Secret Sharing)
- ERC-4337 UserOperation 签名(可合并入EIP-712 签名)

### 5. 其他需求

- WalletConnect v2
- 智能合约钱包个性化配置
- 内置DAPP
- KYC身份
- NFT图片展示

### 1. **用户/企业（User）**

- 每个用户可以拥有多个**钱包（Wallet）**
- 用户的身份不直接关联某种密钥类型，而是管理多个异构的钱包实体
- 用户功能包括：
  - 创建/导入钱包
  - 删除/隐藏钱包
  - 管理钱包标签（如“主钱包”、“质押钱包”等）
  - 切换当前操作钱包
  - 更换钱包密码
  - EIP7702升级账户
  - 指定钱包+网络进行交易

------

### 2. **钱包（Wallet）**

- 钱包是用户的使用单位
- 每个钱包具备以下属性：
  - **名称标签**：如“主钱包”、“冷钱包”
  - **钱包类型**：如 linklogis钱包、metamask钱包、硬件钱包、智能合约钱包
  - **连接状态**：是否连接中
  - **地址**（或多个地址）
  - **资产总览**：包括代币余额、NFT
  - **交易历史**
  - **ENS 支持**
- 钱包支持创建、导入、导出
- 支持的类型包括:
  - 助记词（全链）
  - 私钥 （指定单链）
  - MPC 密钥（全链）
  - 硬件钱包（Ledger、Trezor、Keystone）（全链）
  - 合约钱包（ERC-4337、EIP-7702、Safe）（EVM链）
  - 第三方钱包接口（MetaMask、OKX 等）（根据钱包能力支持的链）

------

### 3. **账户（Account）**

- 账户钱包内部的技术实现实体，负责密钥持有与签名操作
- 地址是账户的外在表现形式，每个账户与特定链强关联（Polygon地址、Solana地址、XRPL地址等）

账户需具备能力有使用的钱包决定：

- 地址获取
- 交易/数据签名（含 raw tx、TypedData、ERC-4337 UserOp）
- 链相关操作（构造/广播交易）
