## Pump.fun

Pump.fun 是 Solana 上的**一站式 meme 币发行 + 初期交易 + 自动流动性迁移平台**。

一句话概括：

> **任何人只需约 1 SOL，就能一键生成新币，并通过 Bonding Curve 完成早期交易和价格发现。达到条件后，这个币会“毕业”（迁移）到外部 DEX 或 PumpSwap，形成真正的交易市场。**玩法原理是FOMO 曲线买盘和毕业冲击波（毕业拉盘）

### **一、发币机制（Token Creation）**

任何用户可以在 Pump.fun：

- 设置代币名称 / 符号
- 上传头像
- 设置简单描述

消耗费用（约 1 SOL 左右，用于部署合约 + 平台费）。
 Pump.fun 会自动：

- 创建 mint（代币）代币总发行量都是10亿，精度6，成功发射后 LP 的自动燃烧和合约权限的完全放弃。
- 初始化 Bonding Curve 市场

**所有代币无需写代码，也无需 LP 管理。**

### **二、Bonding Curve（粘合曲线）定价机制**

这是 Pump.fun 的核心。

💡 什么是 Bonding Curve？

> 一个基于数学公式的价格曲线。随着更多人买入，价格自动提升。
>
> 其定价公式遵循 **x \* y = k** 的恒定乘积规则。
>
> Pump.fun 的 Bonding Curve，本质是一个写死参数的 AMM（常数乘积 + 虚拟初始储备）+ 目标是让 800M token 从超低价一路涨到“毕业价”，同时筹集一笔 SOL。如何以x 为买入 $SOL 数量，价格p对x是二次函数形态
>
> ![image-20251128174435276](C:\Users\顾宇翔\AppData\Roaming\Typora\typora-user-images\image-20251128174435276.png)
>
> 其中 x 为用户购买的 SOL 数量，y为获得的代币数量，随着 x 增加，代币数量减少，价格上升。绑定曲线的初期价格陡峭，适合 Memecoin 的高波动性特点，早期用户可享受较低价格，而后期随着购买增多，价格逐渐平稳上升。这种模型为早期投资者提供了激励，同时确保了代币的流动性。



Pump.fun 使用的曲线接近 **线性 + 库存递减模型**，即：

- 初始价格极低
- 买得越多，价格上涨越快
- 早期买家最便宜

你可以理解为：

**Bonding Curve 是项目早期的临时市场（内盘），用于价格发掘。**

在这个阶段：

- 买入资金进入“池”
- 系统出售代币库存（不是用户互相买卖）
- 还不存在外部 LP，也没有 AMM



### 平台如何赚钱（Fees）

Pump.fun 主要收入来自：

1. 创建费（Mint Fee）

创建代币支付约 **1 SOL** → 平台收入。

2. Bonding Curve Trading Fee

通常为约 **1% 左右的买卖税**（按版本可能略变）。

3. 毕业迁移费（以前）

在代币上线 Raydium 流动性池时，平台收取 **6 SOL** 的上币费
早期版本迁移到外部 DEX 要付几 SOL，现在因 PumpSwap 出现大幅下降。

PumpSwap 推出后，迁移成本大幅减少，提升了平台活跃度。



### 毕业机制（Graduation）= 上池 / 上线外盘

当一个 Pump.fun 创建的代币达到特定条件，就会自动“毕业”。

用户通过 PUMP.FUN 平台的买卖操作，共募集到 **85 SOL**，兑换得到 **8 亿枚 Memecoin 代币**。

募集的 **85 SOL** 中，**79 SOL** 用于初始流动性池（6 SOL 作为上币费）。额外**2 亿枚代币**，和79 SOL 一起添加至 Raydium 的流动性池，使最终代币总量达到 **10 亿枚**。

早期毕业是上 Raydium

后来 Pump.fun 推出自己的 PumpSwap
→ 让整个流程更封闭、更快、更便宜。

代币 在 Raydium 上线时的每枚代币价格为 **0.00000041 SOL**，是初始虚拟池价格的 **14.64 倍**，上线瞬间市值达到 **410 SOL**。

为什么有毕业机制：
**Bonding Curve 只是一个“临时市场（内盘）”，它的数学结构无法长期支撑自由交易（尾部价格飞天）；
 要成为真正的代币市场，就必须迁移到 AMM（外盘）才具备持续流动性、完整价格发现和开放订单流。
 这是从“发币阶段”进入“交易阶段”的必要步骤。**

另外
Bonding Curve 是 **封闭系统**：
 只能在 Pump.fun 内部买卖。

## Raydium

混合 AMM + Order-Book（Hybrid DEX）

> **AMM 池的流动性会同时输入 Solana 的订单簿（原 Serum，现在多是 OpenBook）
> 所以 AMM 和 Orderbook 的深度是共享的。**

**Raydium 自动把 AMM 的报价 → 挂上订单簿，成为 Maker**

围绕中间价创建多级限价档位

Raydium 将 AMM 曲线附近的点“离散化”：

例如：

- P×(1−0.2%)P \times (1 - 0.2\%)P×(1−0.2%)
- P×(1−0.1%)P \times (1 - 0.1\%)P×(1−0.1%)
- PPP
- P×(1+0.1%)P \times (1 + 0.1\%)P×(1+0.1%)
- P×(1+0.2%)P \times (1 + 0.2\%)P×(1+0.2%)

在这些价格点 → Raydium 会自动生成挂单，数量按 AMM 曲线计算。

这些挂单就是 Raydium LP 在订单簿上的深度表现形式。

订单簿的买卖单 → 被 Raydium 用来做 Taker 交易



**优点：**

提升深度

AMM 的深度 + 订单簿外部做市商深度
→ 价格更稳、滑点更低。

**缺点**

AMM LP 的“赚手续费”机会被做市商机器人吃掉

链上订单薄撮合延迟高，撮合不完全实时（区块驱动），交易成本高，导致高频交易能力非常有限，完全无法与中心化撮合速度相比



### 交易执行逻辑

Raydium 会执行“最优路径逻辑”：

逻辑如下：

1. 查询订单簿最优挂单
2. 查询 AMM 当前曲线价格
3. 谁更便宜/滑点更低，就走谁

举例：

- 若有人挂了更低价格的卖单
  → Raydium 或聚合器会吃订单簿（更便宜）
- 若订单簿深度不足
  → AMM 提供连续流动性补充

限价单

Raydium 本身其实没有独立订单簿，它把你的限价单挂到 *OpenBook（旧称 Serum）订单簿*。

当满足条件时

1. 其他用户的市价单
2. AMM 自动吃掉你的挂单（Raydium Taker 行为）
