# CrossChain

## 1. 市场

- Circle CCTP：Circle 开发的协议，旨在帮助实现 USDC 的多链发行，基于Circle 服务提供跨链服务
- Wormhole：基于wormhole守护者节点 (Guardians) 提供跨链服务。
- Across：Optimistic 桥协议，通过中继者和 Optimistic 预言机提供跨链服务。
- Stargate：LayerZero 团队开发的应用层跨链桥，基于中继器和预言机协作提供跨链服务。
- Meson：采用哈希时间锁定完成跨链传输。
- Axelar：基于Cosmos SDK开发的权益证明（“PoS”）网络充当通信层，提供跨链服务。
- Chainlink CCIP：基于Chainlink去中心化预言机网络（“DON”）提供跨链服务。
- L2原生跨链桥：基于L2 Rollup的技术架构进行跨链传输。

## 2. 跨链的类型

### 2.1 跨链机制

1. **公证人机制（Notary schemes）**:公证人机制本质上是一种中介的方式。具体而言，假设区块链A和B本身是不能直接进行互操作的，那么他们可以引入一个共同信任的第三方作为中介，由这个共同信任的中介进行跨链消息的验证和转发。

2. **哈希锁定（Hash-locking**）: 哈希锁定技术最早起源自比特币的闪电网络。其典型实现是哈希时间锁定合约HTLC(Hashed TimeLock Contract)。哈希锁定的原理是通过时间锁和哈希锁来达到资产的原子交换。迫使资产的接收方在deadline内确定收款并产生一种收款证明给打款人，否则资产会归还给打款人。收款证明能够被付款人用来获取接收人区块链上的等量价值的数量资产或触发其他事件。

3. **侧链/中继链（Sidechains / Relays）**: 侧链是指完全拥有某链的功能的另一条区块链，侧链可以读取和验证主链上的信息。主链不知道侧链的存在，由侧链主动感知主链信息并进行相应的动作。

4. **乐观：** 挑战窗口期间的欺诈证据

5. **轻量级/zk客户端**： 链式共识或有效性证

   

### 2.2 跨链代币框架

1. **锁定-铸造：**跨链桥提供商将用户存放在原生链上的代币托管锁定在智能合约中，并通过部署在目标链上的代币合约创建原生代币的「包装」代币版本。当用户希望反向跨链（目标链→原生链）时，将包装代币销毁，并从原生链上的托管账户中解锁原生代币，实现跨链传输的同时维持代币可流动总量。

   缺点：跨链所得非原生代币，不方便后续使用。

2. **销毁-铸造：**跨链时销毁源链上的代币，在目标链上铸造等量的代币；反向传输时，跨链代币在目标链上被销毁，然后在源链上铸造新的代币，实现跨链传输的同时维持代币总供应量。

   缺点：只有代币发行方有权销毁的代币无法跨链。

3. **流动性池：**跨链时在源链上将代币转入流动性池中，在目标链上的流动性池中释放等量的代币。用户得到的代币是各自的链上的原生代币，而流动性提供者可以分红跨链桥的手续费收益。

   缺点：流动性枯竭和单边挤兑风险

### 2.3 跨链数据类型

- Data only ：跨链消息不涉及 Token 传输，而是与合约地址交互的方法和参数；
- Token only：跨链消息仅涉及 Token 传输，dApp 没有附加额外的内容。那么这就是一个单纯的 Token 传输动作；
- Token+Data：跨链消息不仅包含 Token 传输，还包含额外的内容，这些内容可能是一组指令，比如要把 Token 质押或者交换，跨链要完成 Token 的传输，然后需要目标链上的 dApp 合约执行额外的操作；

### 2.4 跨链数据传输方式

- **推**

  A 发送消息，B 收到消息。

- **拉**

### 2.5 **关键考虑因素：**

- **消息排序**：消息是否必须按顺序到达，还是可以独立处理。

- **送达保障**：处理网络故障，确保邮件不会丢失或重复发送。

- **重放保护**：防止同一条消息被多次执行

- **执行与手续费管理**：每条跨链消息都需要有人在目标链上提交交易并支付 gas 费用。这就造成了一个经济协调问题：**消息发送者与执行成本产生者位于不同的链上**。执行器是外部服务，负责监控已验证的消息，并支付 gas 费用以在目标链上执行这些消息。

  **执行责任**：交付方式是无需许可、自动化还是手动
  **Gas 资金**：目的地链费用如何支付以及由谁支付。
  **经济激励**：通过合理的收费市场和激励机制确保可靠的服务交付。

### 2.6 完整的跨链消息流

1. 链上**发送：用户调用方法，合约更新状态并通知传输层**
2. **通知**：传输层通知验证网络生成关于 A 端所发生事件的证明/证明文件。
3. **标记为已验证**：验证器网络在 Chain B 的传输层中将消息标记为已验证。
4. **检测**：执行器检测到已验证的消息已准备好发送
5. **交付与执行**：执行器调用传输层将消息交付到目标合约



## 3. 具体产品

### 3.1 Layerzero

Oracle预言机和Relayer中继器协作成为跨链公证人的角色，提供跨链通信服务

**超轻节点 Ultra-Light Node (ULN)**：轻客户端是需要同步并验证对方链区块头，存储区块头的序列，开销很大，超轻节点信任由预言机提供的区块头，不再从头开始的区块头序列

预言机负责向目标链提供区块hash，告知目标链用户的跨链请求所在的区块hash

中继器负责将跨链消息具体数据 和 Merkle Proof 信息传递到目标链上的合约用以验证并执行

![image-20250109133022602](C:\Users\顾宇翔\AppData\Roaming\Typora\typora-user-images\image-20250109133022602.png)

工作流程：

1. 用户应用程序 UA（如 Stargate 桥）LayerZero 的通信器（Communicator）发送请求，包括交易标识符 t、从 A 到 B 转移的数据（payload 有效负载）、或指向 Chain B 上用户应用程序智能合约的标识符或者中继器 (relayer_args) 等交易信息。
2. 通信器将这些数据以 LayerZero 数据包（packet）的形式发送给验证器（Validator）
3. 验证器将交易标识符和链 B 上智能合约的标识符等发送给网络层（NetWork）。网络层的工作也被触发，发出事件需要通过 oracle 将源链 A 的区块头发送到目标链 B。
4. 验证器将此信息（packet）转发给中继器。中继器被通知后则取交易证明链下存储
5. 预言机获取 Chain A 上当前块的块头，并将其发送到 Chain B
6. 中继器将证明和跨链信息发送到 Chain B，chainB 验证Merkle Proof和区块hash，验证通过转发到应用合约进行执行。



特点：

拆分成预言机和中继器独立运行，在区块链上验证区块时，需要预言机转发区块头、中继器转发交易证明。双重机制交叉验证，生态方可以自建Relayer加上引入第三方Oracle来确保了跨链消息的安全性，即避免了项目方单方面作恶，也避免了预言机单方面作恶。

LayerZero认为应用方才是跨链安全的最终责任人，因此 LayerZero 允许应用方自选 Oracle，自己运行 Relayer。

LayerZero 利用已建立的预言机 Chainlink，这意味着这种新网络在最坏的情况下安全性也只是下降到和预言机一样安全。

只有Oracle 和Relayer 的积极串通的情况下才能破坏安全性，但Relayer也是去中心化的，不同用户应用运行他们自己的 Relayer，风险模型上做了隔离，另外应用要对自己的Relayer负责才能保障项目的信誉



拓展性：LayerZero的链上合约endpoint的架构设计中使用Libraries合约规定了不同区块链的跨链通信规则，再发起跨链请求时根据目标链标识找到相应的Libraries合约处理跨链信息，让LayerZero能够快速拓展支持更多网络，



**LayerZero 核心应用层产品：Stargate**

Stargate 是 LayerZero 团队开发的应用层跨链桥，Stargate使用资产流动池模式，不需要锁定和铸造合成资产，保障了代币原生性

**统一流动性：**Stargate为所有支持跨链的网络提供了共享的统一流动性资产池，不需要创建成对资金池分散流动性，将单币资产在各条链上的流动性作为一个完整的流动性池来利用，尽量了避免单链枯竭

**Delta 算法**：使用资源平衡算法Delta进行调仓平衡，来动态调节流动性在不同 LP 池的深度，流动性池被动态地分割为多个部分（软分区），流动性池的资金被动态分配到不同的区块链，确保每个区块链都有足够的流动性来处理交易请求，在流动性紧张时，不同区块链之间的流动性池可以相互借用，以确保交易顺利进行



### 3.2 Meson

Meson使用了哈希时间锁定技术，这是一种去中心化的交换协议，它可以让不同区块链之间的资产进行无信任的原子交换

**哈希时间锁定合约（HTLC）**：

Meson 智能合约将提供一个流动性池，流动性提供者LP将Token注入到池中，用于后续的跨链交换匹配

1. **兑换请求：**用户在链下构建兑换请求，其中指定兑换金额、初始链（X）、目标链（Y）和代币类型以及其他必要信息。授权 Meson 合约锁定兑换金额 + 匹配 LP 的兑换费。签名后的兑换将通过[Meson 中继器](https://docs.meson.fi/protocol/system-design/relayer)广播到 LP 网络，并等待目标链的 LP 匹配。
2. **发布并绑定互换：** LP 收到互换请求后验证同意后，LP 可以[`postSwap`](https://github.com/MesonFi/meson-contracts-solidity/blob/main/contracts/Swap/MesonSwap.sol#L36)在初始链 X 上调用 Meson 的方法发布互换，Meson 合约将用户的互换金额 + 手续费转入到一个合约中，并锁定一段时间（暂定为 1-2 小时），只有用户的签名才能解锁资金到绑定的LP地址中。
3. **锁定互换：**对于成功绑定互换的LP，其需要[`lock`](https://github.com/MesonFi/meson-contracts-solidity/blob/main/contracts/Pools/MesonPools.sol#L79)在目标链Y上调用Meson的方法锁定互换资金（暂定20分钟）并指定接受的用户地址，需要用户提供可验证的签名才能提取资金，以确保用户能够收到付款；
4. **释放签名：**用户在确认步骤 2 和 3 中的交易后，需要构造一个在锁定期内释放资金的签名，指定接收者地址，并广播通知。
5. **释放资金：**用户的释放签名公开后，任何人（包括用户自己）都可以[`release`](https://github.com/MesonFi/meson-contracts-solidity/blob/main/contracts/Pools/MesonPools.sol#L127)在目标链Y上调用Meson合约的方法。执行此交易时会检查签名的有效性。步骤3中锁定的资金将支付给用户指定的接收者；
6. **获得初始资金：**最终LP使用同样的释放签名，调用[`executeSwap`](https://github.com/MesonFi/meson-contracts-solidity/blob/main/contracts/Swap/MesonSwap.sol#L112)初始链X上Meson合约的方法，获取用户初始存入的资金（包括互换费）。LP可以选择将这部分资金提现，也可以将其转移到自己在链X上的流动性池中。

这个过程的关键点在于，签名可以解锁两个独立的、不相关的区块链上的交易，控制两个交易同时完成或撤销。两个交易的时间锁定具有时间差，保障双方有一定的时间提取各自的资金



### 3.3 USDC CCTP

USDC CCTP是官方提供的底层USDC跨链协议，而不是跨链桥应用，可以在Circle官方部署过USDC合约的链之间进行跨链。

1. USDC 的所有者发起将 USDC 从一个区块链转移到另一个区块链的转账，并指定目标链上接收方钱包地址，合约会销毁源链上指定跨链数量的的USDC并会发出一个事件交易
2.  Circle 的证明服务自动监听该事件，会提供一个可以铸造等量的USCD的签名，发起 跨链的应用程序负责调用 Circle 的API获取签名证明，然后使用该铸造授权签名在目标链上给指定地址铸造 USDC。

CCTP 是免许可的，无需许可的基础设施这意味着任何第三方开发人员都可以访问它以集成到他们的应用程序中，并且不需要注册帐户。开发人员还可以在他们的应用程序中基于 CCTP 构建新应用程序将 USDC 移动到任何受支持的区块链。



### 3.4 其他

#### **Wormhole**

Wormhole由19个守卫者节点组成的PoA共识网络提供安全保护，这些守卫者是负责监控链活动和验证消息的节点。每个连接的区块链都有一个Wormhole核心合约，作为跨链App的主接口。

1. 通过Wormhole核心合约发送的消息将转发给守卫者，由守卫者独立验证和审批消息的真实性。
2. 当绝大多数（三分之二）的守卫者对消息进行验证后，该消息就会封装成一种称为“可验证操作批准”（VAA）的结构。
3. 随后，中继器会将VAA传输至目标链进行执行。

19个受信任的守卫者节点由具有资本背书和声誉背书的主体参与，包括Jump Crypto、Everstake 和 FTX（FTX已退出，目前是18个守卫者节点） 等加密货币行业中信誉良好的实体运行，因为Wormhole对以太坊和Solana、Sui之前的跨链支持较早，因此获得了很多生态用户



#### **Chainlink CCIP**

CCIP是由Chainlink的去中心化预言机网络DON作为基础设计的跨链服务

![image-20250108161211276](C:\Users\顾宇翔\AppData\Roaming\Typora\typora-user-images\image-20250108161211276.png)

CCIP 由 6 个链上合约和 3 组链下代理组成。

链上合约分别是：Router 合约、OnRamp/OffRamp 合约、Tokenpool 合约、Commit Store 合约 和 RiskManagementNetwork 合约

链下组件则分别是：Commiting DON、Executing DON、RiskManagement Network（风险管理网络）

工作流程

1. Committing DON 负责监听源链上的 OnRamp 合约发出的跨链事件，当检查到新的请求时，等待它在源链上达成最终性，然后计算最新的消息根，把该消息根写入目标链上的 CommitStore 合约（每个通道有一个 CommitStore 合约和 RiskManagementNetwork 合约。前者负责管理消息根的队列，后者负责维护风险管理网络节点的公钥，并维护祝福签名和诅咒签名的阈值）
2. 风险管理网络负责复核 Committing DON 在 CommitStore 签名的消息根。风险管理网络中的每个节点也会去计算消息根，并和 Commiting DON 提交到 CommitStore 合约中的消息根进行对比，如果一致，就会去 “祝福” 这个根，如果不一致，就会去 “诅咒” 这个根。
3. Executing DON 也会监控源链上 OnRamp 合约发出的事件，然后将消息原文投递到目标链的 OffRamp 合约，然后等待它被最新的消息根包含并被风险管理网络 “祝福” 后，触发 OffRamp 合约对消息进行验证和后续的执行



**双安全层**：通过工作网络（Commiting DON）和监督网络（风险管理网络）的交叉验证来保证跨链消息的安全传递。风险管理网络是一个独立的监督网络，持续监控和验证 CCIP 工作网络的行为，通过独立验证跨链操作是否存在错误来提供额外的安全保障。一旦风险管理网络报告错误，或者停止工作，CCIP 的跨链服务就会被紧急关停，直到通过治理投票恢复

CCIP的架构将交易承诺与交易执⾏分开，为通过风险管理网络进行二次审批和异常检查提供了更多时间

**速率限制：**CCIP 支持对给定时间段内能够传输的 Token 数量进行可定制的速率限制，可以设置最大容量、再填充速率

**智能执行：**可以设置最大Gas锁定，倘若目标链 Gas 上涨，CCIP 的 Executing DON 会尝试提高 Gas Limit 去重试执行，如果反复重试或是超时（超过 1 hour）依旧不能执行成功，CCIP 会停止重试，用户可以在 CCIP 浏览器中手动重试，手动重试需要自费支付目标链上的 Gas



#### **Axelar**

Axelar是一个用 Cosmos SDK 开发，基于Cosmos权益证明（“PoS”）为共识的跨链通信层，供DApp在EVM和Cosmos生态系统之间进行交互，Axelar网关和验证者节点监控网络状态、验证交易并管理跨链通信

**共识：**控制跨链网关的多重签名密钥由所有验证者共同持有，每个验证者所持有的分享密钥份额由其质押的 AXL 代币数量来决定，在传输跨链信息和执行跨链操作时，需要达到阈值数量的验证者节点确认完消息的真实性并提交分享密钥，网关才能提交目标链的跨链交易。另外密钥分片会定期更新重新分配给验证者防止泄露。

**平方投票：**为了降低由于 AXL 质押份额不同，导致投票权集中于少数利益相关者的风险，在共识层面 Axelar 还引入了「平方投票」机制，即当验证者进行投票时，其获得一个份额的投票权，需要质押一个单位的 AXL 代币，但是如果其需要获得两个份额的投票权，则要质押二的平方，即四个单位的 AXL 代币，以此类推，验证者节点所拥有的代币份额，需要开完平方以后才能获得相应数量的投票权。在限制了高质押份额的验证者节点以后，网络的去中心化程度有了更大的提升。

**AVM: **Axelar 在 CosmWasm 的基础上开发了 Axelar 虚拟机，支持开发者在 Axelar 上编写智能合约，以实现跨链任务，让 Axelar 从一个负责消息和资产传递的跨链层进化为了一个可以进行编程和部署智能合约执行更复杂操作的跨链层。



#### **Across**

Across是Optimistic 桥协议，通过中继者和 UMA的乐观预言机提供跨链服务。

**OP Bridge:** 引入了挑战窗口期的概念和一个名为 “挑战者” 的角色。在乐观验证桥中，消息在被验证后，不会立刻进入执行环节，而是会进入一个计时环节，计时结束后，如果没有挑战者对该消息提出质疑，该消息才会进入执行环节，被 Taregt dApp 执行。

如果挑战者对消息进行质疑，那么该消息将被标记为 “不可信”，“不可信” 消息将不会进入执行环节，挑战者将会把它提交回源链，由源链的仲裁合约进行仲裁，如果消息在源链真实存在则证明挑战者误报，如果消息在源链并不存在则证明 Bridge Nodes 欺诈，签名了虚假的消息。仲裁结束后，会给诚实的一方奖励，而惩罚不诚实的一方

**双模型：**为了减少用户等待的挑战窗口期，中继器预先向用户提供资金，为了获取经济激励，中继者愿意等待挑战窗口完成并承担风险。因此用户的小额转账或是非敏感操作会直接跳过挑战窗口期，只有大额转账或者敏感操作，才会有挑战窗口期，通常，可以在 1–2 分钟内收到跨链的资金，交易的速度取决于这些中继器的速度，如果在挑战期间有争议，用户不会受到任何处罚，由中继器承担损失



#### **zkBridge**

ZK Bridge 的实现是轻客户端加中继器的方案，轻客户端是需要同步并验证对方链区块头，存储区块头的序列，开销很大，

ZK Bridge的轻客户端通过ZK技术在链下验证对方链的新区块头，并将新区块头及其有效性证明（Zk Proof）一并提交到链上，链上可以直接验证 ZK Proof，即可等效于验证新区块头，将验证通过的区块头记录在链上。

 zkBridg的证明者节点获取源链上指定高度的区块头，使用zkSNARKS为区块头生成证明，发送到链上并获得奖励，链上轻客户端仅需验证 ZK proof，比计算所有新区块交易验证新区块头的轻客户端的开销大幅缩减。另外使用硬件加速和递归证明提高了生成ZK证明的速度。

目前 zkBridge 可以在 2 分钟内生成一个区块头的 ZK-SNARK 证明，然后在以太坊端，验证费用是小时 230k gas 



## 4. 技术选择

Wormhole：19个验证者的模式相对中心化，FTX已退出，目前是18个守卫者节点

Axelar：需要进行节点验证和网络共识，目前75个节点还是共识不够，节点质押的几百万美金金额的管理上亿的跨链资金还是不够安全。

Layerzero：LayerZero 假设应用方不会做对自己不利的事情，但这个假设实际上是有问题的，应用方有可能会 rug-pull，应用方内部也可能会出现疏忽、渎职的情况。

ZKBridge：性能和成本难以突破限制，以 EVM 为例，验证一个 ZK proof 的成本大约在 300k~500k gas 之间，和外部验证桥只需验证一个签名的 21k Gas 相比，高了 20 倍左右，这最终还是会转化为前端用户高昂的跨链费用。性能方面zk证明需要一定时间，甚至一些系统对 ZK 不友好（例如 SHA 等）的情况也时常发生，导致证明生成时间过长，硬件加速等方式，但硬件加速其实也仅限于提高部分效能。另外ZKP的技术难度大、开发工程难度大，很难适配新的异构链。

Across：OPBridge挑战窗口期的存在增加了用户的等待时间，就算通过中继器质押提供流动性，对于大额跨链资金仍然需要等待时间。

Chainlink CCIP：双安全层模型中Commiting DON 和风险管理网络的隔离可能有问题，无法排除运营商同时参与两个网络或者不会联合作恶

Meson：HTLC 主要适用于简单的原子交换类型的交易。当涉及到跨链信息传输需要执行复杂逻辑的跨链操作时，HTLC 的模型无法很好地处理，另外时间锁机制也意味着跨链延迟，影响跨链速度，哈希锁的机制意味着只能在支持相同哈希函数的区块链之间进行跨链



每个跨链技术目前都有优缺点，目前最安全的是Meson、ZKBridge，性能最快的是Layerzero、Wormhole、Axelar、Across、Chainlink CCIP，因此需要综合考虑安全性、性能（速度快、费用低）、连接广度（接入的链的数量）、传输数据类型然后做出选择。

对与自己私链的跨链，结合开发和搭建难度，建议使用Meson技术

### 5.1 蚂蚁链“两链一桥”平台：

资产链：负责将国内的实体资产进行通证化，将其转化为链上的可交易资产。这个过程首先采集并验证资产的核心信息

交易链：支持通证化资产的市场化流转，使得全球投资者可以随时加入资产的融资过程

蚂蚁链可信跨链桥：桥接资产链和交易链，确保两链之间的数据和资产流通的合规与安全，该桥能够确保内地资产链和香港交易链之间的无缝对接，还通过多重身份验证和数据加密技术确保资产和资金的跨境合规

常规融资：

已在香港金管局 Ensemble 项目中得到应用，今年 8 月协助内地新能源上市公司朗新完成了 1 亿元跨境融资。目前，蚂蚁链已累计为超过 1200 万台新能源设备提供上链服务，成为国内最大的新能源区块链设备平台。

国际贸易：

1. 香港买家A希望向内地卖家B购买货物但短期内缺乏流动资金且无法从银行获得贷款时，买家A可以在B提供的货单估值后上链，金融机构利用智能合约为通证设定使用规则，包括本息结构、还款期限和结算条件
2. 投资者C购买Token为A提供融资，融资款将直接转入卖家B的账户，无需经过买家A的中转，而C则持有提货凭证以确保交易顺利进行
3. 在A完成本息支付后，C将提货凭证交给A，A则可凭该凭证完成货物交割。同时，C按合约规定将融资收益分配给参与融资的投资者

## 6. 集成思路

1. 在联盟链中的资产可以通过跨链桥转移到公链上去融资或者交易，因此整个系统中核心企业和供应商都可以获取到融资

​	核心企业通过ABT获取融资 —> 核心企业通过DTT发起Send并锁入资金 —> 供应商的ROR在Abito市场融资 —> DTT为供应商结算打	款 —> 核心企业ABT支付本息后拿到提货单



2. 建立三层结算系统：法币结算层、公链结算层、隐私交易层

   法币结算层与银行API集成，建立法币与数字资产的网关服务，实现法币支付触发链上转账或者链上结算自动触发法币转账

​	公链结算层使用公链网络进行交易和结算。确保资产能够高效、透明、去中心化管理

​	隐私交易层保护交易的隐私性，确保参与方的身份和交易细节不被外界公开

​	跨链桥要满足公链与私链/隐私链的跨链需求、满足法币系统和公链的跨链需求



3. 付款交割（“DvP”）场景使用哈希时间锁的跨链机制完成不同链上的NFT和FT的原子交易
