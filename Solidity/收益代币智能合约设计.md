# 收益代币智能合约设计

目前主流的设计模式可以归纳为以下四大类：

### 1. 余额重算模式 (Rebasing Model)

这是最直观但对开发者最具挑战性的模式。代币持有者的余额会随着收益的产生自动增加。

- **核心逻辑：** 合约通过调整内部的“缩放因子”（Scaling Factor）来改变所有持有者的显示余额，而无需进行实际转账。

- **代表案例：** **Lido (stETH)**、早期 **Ampleforth (AMPL)**、**Aave (aTokens)**。

- **优点：** 用户体验极佳，用户能直接在钱包里看到代币数量不断“跳动”。

- **缺点：** **兼容性差**。

  **A. DEX 的噩梦**

  在 Uniswap v3 这样的协议中，流动性是按价格区间提供的。如果一个代币的余额会自动增加（Rebase），Uniswap 的智能合约会因为无法感知到这些多出来的余额，而导致这些利息无法分配给流动性提供者，甚至导致资金被卡死。

  **B. 跨链桥的阻碍**

  大多数跨链桥（Bridge）只能锁定固定数量的代币并在另一条链铸造对应数量。Rebasing 代币在桥接过程中，由于两端余额同步极难，往往会丢失利息收益。

  为了解决上述问题，现在的行业标准是：**底层可以用 Rebasing，但上层必须 Wrapped（包装成兑换率模型）。**

  - **Lido (stETH vs wstETH)：** 最典型的例子。$stETH$ 是 Rebasing，但所有的 DeFi 操作（如在 Aave 做抵押、在 Uniswap 做 LP）几乎都要求使用 $wstETH$（兑换率模型）。目前 $wstETH$ 的使用率远超 $stETH$。
  - **Aave 的进化：** Aave v3 也推出了 `staticAToken`，本质上就是把 $aToken$ 包装成了类似 $cToken$ 的兑换率模型，以便于跨链和在其他协议中使用。

### 2. 兑换率模式 (Exchange Rate Model)

这是目前 DeFi 中最主流、兼容性最好的模式。

- **核心逻辑：** 代币的数量在钱包中保持不变，但每一单位代币代表的基础资产（Underlying Asset）数量会随着收益积累而增加。
- **公式：** 
  $$
  \text{兑换率} = \frac{\text{资产池总额}}{\text{代币总供应量}}
  $$
  
- **代表案例：** **Rocket Pool (rETH)**、**Lido (wstETH)**、**Compound (cTokens)**。
- **优点：** **极高的可组合性**。它本质上是一个标准的 ERC-20 代币，价格通过汇率反映，完美兼容现有的所有协议。
- **缺点：** 不够直观，用户需要通过前端或查询合约才能知道自己实际赚了多少。

### 3. 收益剥离模式 (Yield Stripping / PT-YT Model)

这是一种进阶的金融设计，通过将资产的“本金”和“收益权”拆分，实现收益的资产化。

- **核心逻辑：** 将一个带息资产（如 stETH）拆分为两个代币：
  - **PT (Principal Token)：** 零息债券，在到期日可按 1:1 兑换本金。
  - **YT (Yield Token)：** 收益代币，代表该资产在到期前产生的所有实时收益。
- **代表案例：** **Pendle Finance**、**Element Finance**。
- **应用场景：**
  - **固定收益：** 用户以折扣价买入 PT，锁定未来收益率。
  - **收益率投机：** 交易者通过买入 YT 来做多未来的 APY（收益率）。

### 4. 收益分派模型 (Distribution Model)

- **逻辑：** 代币价格和数量都不变，收益以另一种代币（通常是稳定币如 USDC）的形式定期分发（类似派息）。
- **应用场景：** 常用于**私人信贷（Private Credit）\**或\**房地产 RWA**。
- **代表：** **Centrifuge**、**Maple Finance**。



------

### 主流模式对比总结

| **模式**          | **余额变化** | **价格变化**    | **DeFi 兼容性** | **典型代表**     |
| ----------------- | ------------ | --------------- | --------------- | ---------------- |
| **Rebasing**      | 动态增加     | 锚定基础资产    | 低 (需包装)     | stETH, aUSDC     |
| **Exchange Rate** | 固定不变     | 随收益上涨      | 极高            | rETH, wstETH     |
| **PT/YT Split**   | 固定不变     | PT 折价/YT 波动 | 中 (需专门市场) | Pendle           |
| **ERC-4626**      | 视实现而定   | 视实现而定      | **标准化最高**  | Yearn V3, Morpho |



### 现状：谁更好？

**结论：兑换率模型（以及“非重基”代币）已经成为 DeFi 的底层基础设施标准。**

- **对于开发者：** 几乎 100% 会选择**兑换率模型**（或称为 Vault 模式，符合 ERC-4626 标准）。因为这能确保你的代币可以无缝进入所有借贷平台、DEX 和收益聚合适。
- **对于普通用户：** **余额重算模型**（Aave 模式）在“钱包展示”层面依然有生命力，因为它符合人类直觉。

> **当前的共识方案：** 协议底层采用类似 Compound 的**兑换率模型**以保证极致的安全性与兼容性，然后在前端界面上，通过 UI 计算显示出“实时利息”，从而兼顾“好用”与“直观”。
