# RWA交易市场智能合约设计

本文档介绍了 RWA（Real World Assets，现实世界资产）在区块链上的二级市场的多种交易模式，其中二级市场需要 **多种交易模式共存**，以适应不同资产和投资者需求。



### 二级市场模式

#### 方式 1：**OTC / 私下交易**

**定义**：交易双方直接链下协商，议价完成，链上只做签署或交割

**适用场景**：大额交易、机构投资者

**流程**：

1. 双方签署合规协议

2. 使用直接转账或托管方完成指定链上资产划转

   

**适用场景**：大宗交易、机构合作

**技术实现**：托管合约 + 线下协议



#### **方式 2：RFQ**

### 角色

- **Requester（询价方）**：买房/卖方发起 RFQ
- **Dealers（做市/报价方）**：返回 Quote



1. **请求报价（Request）**
   - 询价方向对手方发送交易意向。
   - 包含：
     - 交易资产类型（如 RWA 份额）
     - 数量
     - 方向（买/卖）
     - 其他条件（交割日期、结算方式等）
2. **报价（Quote）**
   - 报价方根据资产情况和市场流动性给出 **价格和条款**。
   - 报价通常 **带时效性**，例如 30 分钟有效。
3. **确认交易（Accept/Negotiate）**
   - 询价方决定是否接受报价。
   - 可以继续谈判直到双方确认。
4. **执行（Execution）**
   - 一旦双方确认，智能合约或托管方完成资产划转和资金结算。



**适用场景**：资产流动性低、交易量大、合规要求严格的机构投资者、大宗交易

**技术实现**：托管合约



#### **方式 3：荷兰拍卖**

- **荷兰拍卖**（Dutch Auction）是一种**递减价格拍卖**，价格随时间从 `startPrice` 下降到 `endPrice`（或按曲线）：
  1. 卖方先设定一个高起拍价。
  2. 随时间价格逐渐下降，直到有买方接受当前价格。线性：`price(t)=start - (start-end)*(t-t0)/(t1-t0)`
  3. 拍卖结束，价格即为成交价。

> 核心特点：**价格逐渐下降 → 先到先得**。

------

**流程**

1. **锁定 base（待卖资产），设定参数**
   - 起拍价（高于预期市场价）
   - 起止时间
   - 最低价（一般不低于资产净值）
   - 拍卖时长 T（如 24 小时）
   - 单笔最小/最大购买量
2. **公告拍卖**
   - 投资者收到通知，知道起拍价、最低价、拍卖时间
3. **价格递减**
   - 系统按照预设算法（线性或指数）递减价格
4. **投资者出价**
   - 投资者随时在价格下降期间提交认购意向，以当前价格 `buy(amountBase, maxPrice)` 购买
5. **成交确认**
   - 第一个接受当前价格的投资者成交
   - 若允许多份额认购，可按先到先得或按比例分配
   - 若卖完或到期：结束拍卖；未卖出部分解锁返还。

**技术实现**：价格递减函数合约



**场景**

RWA 通常是低流动性、价格不透明的资产，例如：

- 房地产份额
- 企业债权 / 债券
- 资产证券化产品（ABS / RWA Token）

使用荷兰拍卖的优势：

1. **快速成交**：不用等集合竞价或持续挂单，降低市场僵持。
2. **价格发现**：价格从高到低，自动找到买方愿意接受的价格。
3. **降低交易摩擦**：尤其是大额资产，避免连续订单造成流动性不足。
4. **适合合规投资者**：可以在拍卖前只允许白名单（KYC）参与者投标。



#### 方式 4：**盲拍 / 封闭式拍卖（Sealed Bid Auction）**

**目标**：

所有投资者提交封闭报价，拍卖结束后统一开标。

在提交阶段隐藏出价，防止信息泄露与抢跑；在揭示阶段公开并清算。



**种类**：

- **最高价中标（First Price Sealed Bid）**：最高报价者获胜
- **次高价中标（Vickrey Auction / Second Price Sealed Bid）**：最高报价者获胜，但支付第二高价



**优点**：公平，避免竞价冲击

**缺点**：不适合小额或频繁交易



#### 流程

两阶段/三阶段状态机

1. **Commit 阶段**
   - Bidder 提交 `commit = hash(bidPrice, bidAmount, salt, bidder, auctionId)` 并锁定保证金/报价资产（quote）。
2. **Reveal 阶段**
   - Bidder 提交明文（price/amount/salt），合约验证哈希匹配。
3. **Clearing / Settle 阶段**
   - 根据规则（第一价格/第二价格、统一清算价等）计算成交与退款，Settlement 执行交割。



**适用场景**：

- 大宗 RWA、银行票据、ABS

- 避免价格暴露引起投机

  

**技术实现**：密封报价合约



#### 方式 5：定期拍卖

在一个时间窗内收集订单，窗口结束后按单一清算价（或少量价格层）一次性撮合。

定期拍卖（**Periodic / Batch Auction**）在 RWA 或数字证券化场景里常用于二级市场流动性低、交易不活跃的资产。

它的核心思想是：**集中时间窗口，统一价格清算**，而不是连续交易。

**定义**

- **定期拍卖**：在固定时间周期（如每日、每周、每月）内收集买卖订单，然后统一撮合清算，确定成交价格。
- 适用场景：
  - RWA 二级市场（资产流动性低）
  - 大宗交易
  - 需要价格发现机制的受限资产（白名单交易）

------

**流程**

**Step 1：订单收集**

- 拍卖周期开始 → 平台开启订单收集窗口
- 投资者提交买入/卖出意向：
  - 数量
  - 价格区间（可选）
- 系统记录所有合规投资者的订单（KYC 校验）

**Step 2：集合竞价（Price Discovery）**

- 拍卖结束 → 系统计算**清算价格（Clearing Price）**：
  - 目标：**最大化成交量**
  - 方法：
    1. 按价格排序买卖订单
    2. 找到能匹配最多份额的价格
    3. 该价格即为成交价格

**Step 3：成交与结算**

- 系统执行：
  - 代币划转（ERC-20 或 ERC-4626）
  - 资金结算（USDT、DAI 等稳定币）

**Step 4：公布结果**

- 成交量、清算价格、剩余未成交订单统计

- 为下一个拍卖周期提供参考

  

**适用场景**：低流动性资产、大宗交易

**技术实现**：集合竞价合约



#### 方式 6：**自动做市商**

AMM 在 RWA 场景的核心价值就是 **提供连续、顺滑、透明的小额兑换体验**，而不是承担大宗或高价值交易。

https://www.techflowpost.com/article/detail_27729.html

------

**核心目标**

1. **小额交易**
   - RWA 通常价值高、流动性低
   - AMM 适合散户或小额投资者，避免大额交易造成市场冲击
2. **顺滑兑换（Smooth Trading）**
   - 通过自动做市公式（x·y=k 或集中流动性曲线）
   - 提供 24/7 交易，不依赖人工撮合或拍卖
3. **透明价格**
   - AMM 的价格由池子状态和算法公式决定
   - 可以结合 oracle 或 ERC-4626 vault 的净值（NAV）更新，保证价格接近真实市场价值

------

**实现方式**

**(a) RWA Token / Stablecoin AMM 池**

- 投资者用稳定币（USDT/DAI）换 RWA Token
- AMM 保证兑换顺滑，价格变化可控
- 适合零散投资者、小额二级交易
- 为 AMM 池提供奖励（治理代币或收益分成）
- 吸引流动性提供者，减少滑点
- Oracle 更新 NAV 定价
- ERC-4626 vault 结合稳定币池

#### **方式 7：KYC 订单簿**

- 投资者在平台上挂买/卖单，系统验证 KYC。
- 智能合约只允许白名单地址交易。
- 交易可以是：
  - **限价订单**：指定价格等待撮合。
  - **市价订单**：直接匹配当前报价。

**技术实现**：白名单合约 + 撮合引擎

**案例**：INX、tZERO
