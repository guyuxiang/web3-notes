# Cosmos应用

应用链的实现过程：

初始化编解码工具cdc,codec - 提供负责Cosmos编码格式的工具——Amino。相比Protobuf，Amino增加了对接口类型编解码功能的支持。为了使用Amino对接口类型进行编解码，需要将接口类型和实现了该接口类型的具体类型一同注册到编解码器中，需要注册的数据类型主要有各个模块定义的数据类型，Cosmos-SDK定义的数据类型，密码学功能相关的数据类型，Tendermint Core定义的举证类型

Cosmos-SDK提供了应用模板BaseApp。

在开发自己的项目时使用BaseApp一方面可实现ABCI来与共识引擎互动，另一方面可负责链的初始化，模块的存储、消息路由以及不变量检查等工作。
初始化baseApp时提供应用名字appName、日志记录器logger、数据库db、编解码器cdc、baseAppOptions来创建BaseApp

设置各个模块存储空间和瞬时存储空间，**拥有模块的StoreKey就相当于拥有了各模块的子存储空间的访问权限，因此keys和tkeys字段在初始化后，会传给相应模块的Keeper，保证各模块的存储只由本模块的Keeper来管理。**

sdk.KVStoreKey是持久化存储
sdk.TransientStore 是 KVStore 的内存实现，用于未持久化的状态。

初始化各个模块的Keeper成员变量，**通过Keeper对外暴露的模块调用接口**，**保证模块安全，并实现模块间的互操作**。
由于模块之间可能相互依赖，因此各模块Keeper的初始化顺序也需要合理安排。又由于所有模块的Keeper都需要依赖参数子空间（subspace），因此需要首先创建params模块的Keeper
各模块Keeper的创建都需要**消息编解码器、获取模块存储空间的StoreKey、存储本模块配置参数的参数子空间、标识模块错误类型的错误码以及本模块依赖的其他模块Keeper**。在这些共性之外，有几个模块的Keeper初始化还会需要额外的参数。比如bankKeeper需要所有模块的模块账户地址app.ModuleAccountAddrs()

模块管理器来辅助BaseApp完成对各模块的管理工作，同时实现对业务逻辑的解耦。开发上层应用时可以按需定制模块管理器的行为，从而实现BaseApp对模块的定制化管理。
**模块管理器可以对各个模块的BeginBlock()、EndBlock()、InitGenesis()方法的调用顺序进行管理**，以SetOrderBeginBlockers()方法为例，该方法会按照参数的顺序，将相应模块名存储在模块管理器的OrderBeginBlockers字段中。在处理ABCI的ReqBeginBlock请求时，会遵循该顺序依次调用各模块的 BeginBlocker()方法。

各个模块在其BeginBlocker()方法中定义本模块在区块执行之前的处理操作：mint模块负责区块奖励的增发，distribution模块负责区块奖励与交易费的分发，slashing模块负责对验证者被动作恶行为的惩罚。mint模块增发的资产需要在本区块内通过distribution模块进行分发，因此mint模块的增发逻辑需要在distribution模块之前执行。slashing模块的该方法最后执行，对可用性差的活跃验证者罚没一定比例的抵押资产，这也意味着验证者（以及相关的委托人）在上个区块获得的收益不会因抵押资产减少而受到影响。

最后使用baseApp的创建交易和消息路由，初始化链方法，加载特定版本的状态，并返回新创建的应用。

SDK使用对象能力来访问应用程序状态的各个部分。这是为了允许开发人员采用小权限准入原则，限制错误或恶意模块的去影响其不需要访问的状态的能力。

Msg触发状态转变。Msgs被包裹在客户端提交至网络的Txs中。Cosmos SDK从Txs中打包和解包来自Msgs，这就意味着，作为一个应用开发者，你只需要去定义Msgs。Msgs必须实现Msg接口
包括路由的模块名,消息调用的方法名,输入检验,获取签名

Handler定义了在接收到一个特定Msg时，需要采取的具体处理函数
需要创建NewHandler子路由，它将进入该模块的msg路由到正确的handler做处理

首先在RegisterRoutes函数中为模块定义REST客户端接口。路由都以模块名称开头，以防止命名空间与其他模块的路径冲突：

定义的buyName 和 setName 交易路由。 实际上并不能将交易发送进行买入和设置名称,这些端点构建并返回每个特定交易，然后可以以安全的方式对其进行签名





要使用 IGNITE® 创建新的区块链项目，您需要运行以下命令：

```text
ignite scaffold chain example
```

该`ignite scaffold chain`命令将在新目录中创建一个新的区块链`example`。

新的区块链基于 Cosmos SDK 框架构建，并导入了多个标准模块以提供一系列功能。这些模块包括 `staking`：支持委托权益证明（DPoS）共识机制的模块、`bank` 用于促进账户间同质化代币（FGT）转移的模块以及`gov`用于链上治理的模块。除了这些模块之外，该区块链还导入了 Cosmos SDK 框架中的其他模块。

该`example`目录包含构成 Cosmos SDK 区块链结构的生成文件和目录。其中包括链配置、应用程序逻辑和测试等文件。它为开发人员提供了一个起点，以便快速设置新的 Cosmos SDK 区块链并在其上构建所需的功能。

`example`默认情况下，IGNITE® 会在目录中创建一个与正在创建的区块链同名的空自定义模块（在本例中为 `<blockchain_name> `） `x/`。该模块本身没有任何功能，但可以作为构建应用程序功能的起点。如果您不想创建此模块，可以使用 ` `--no-module`--skip` 标志跳过此步骤。

## 目录

为了了解 IGNITE® CLI 为您的项目生成了什么，您可以检查`example/`目录的内容。

该`app/`目录包含连接区块链各个部分的文件。其中最重要的文件是 ` `app.go`<blockchain_type>`，它包含了区块链的类型定义以及用于创建和初始化区块链的函数。该文件负责将区块链的各个组件连接起来，并定义它们之间的交互方式。

该`cmd/`目录包含负责编译后二进制文件命令行界面 (CLI) 的主要软件包。该软件包定义了可通过 CLI 运行的命令及其执行方式。它是区块链项目的重要组成部分，因为它为开发者和用户提供了一种与区块链交互并执行各种任务（例如查询区块链状态或发送交易）的方式。

该`docs/`目录用于存储项目文档。默认情况下，该目录包含一个 OpenAPI 规范文件，该文件采用机器可读格式定义软件项目的 API。OpenAPI 规范可用于自动生成项目的人类可读文档，并为其他工具和服务与 API 交互提供途径。该`docs/`目录还可用于存储与项目相关的任何其他文档。

该`proto/`目录包含协议缓冲区文件，用于描述区块链的数据结构。协议缓冲区是一种与语言和平台无关的结构化数据序列化机制，常用于分布式系统（例如区块链网络）的开发。目录中的协议缓冲区文件`proto/`定义了区块链使用的数据结构和消息，并用于生成可用于与区块链交互的各种编程语言的代码。在 Cosmos SDK 的上下文中，协议缓冲区文件用于定义区块链可以发送和接收的特定数据类型，以及可用于访问区块链功能的特定 RPC 端点。

该`testutil/`目录包含用于测试的辅助函数。这些函数为编写区块链测试时执行常见任务（例如创建测试账户、生成交易和检查区块链状态）提供了便捷的方式。通过使用目录中的辅助函数`testutil/`，开发人员可以更快速高效地编写测试，并确保测试的全面性和有效性。

该`x/`目录包含已添加到区块链的自定义 Cosmos SDK 模块。标准 Cosmos SDK 模块是预构建的组件，为基于 Cosmos SDK 的区块链提供通用功能，例如质押和治理支持。而自定义模块则是专门为区块链项目开发的模块，提供项目特定的功能。

该`config.yml`文件是一个配置文件，可用于在开发过程中自定义区块链。该文件包含控制区块链各个方面的设置，例如网络 ID、账户余额和节点参数。

该`.github`目录包含一个 GitHub Actions 工作流，可用于自动构建和发布区块链二进制文件。GitHub Actions 是一款工具，允许开发人员自动化其软件开发工作流程，包括构建、测试和部署项目。该 `.github`目录中的工作流用于自动化构建和发布区块链二进制文件的过程，从而节省开发人员的时间和精力。

该`readme.md`文件是一个自述文件，概述了区块链项目。该文件通常包含项目名称和用途等信息，以及如何构建和运行区块链的说明。通过阅读该`readme.md`文件，开发人员和用户可以快速了解区块链项目的用途和功能，并开始使用它。





## 启动区块链

要在开发环境中启动区块链节点，您可以运行以下命令：

```text
ignite chain serve
```



该`ignite chain serve`命令用于在开发模式下启动区块链节点。它首先使用该 `ignite chain build`命令编译并安装二进制文件，然后使用该命令初始化单个验证器的区块链数据目录`ignite chain init`。之后，它会在本地启动节点并启用自动代码重载，以便代码更改能够反映在正在运行的区块链中，而无需重启节点。这有助于加快区块链的开发和测试速度。
