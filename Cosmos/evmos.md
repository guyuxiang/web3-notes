# EVMOS

## 一、地址格式对比

| 项目     | Cosmos 地址                                                | 以太坊地址                                   |
| -------- | ---------------------------------------------------------- | -------------------------------------------- |
| 示例     | `cosmos1p9h8f9q0u5a0eh5sgkx6jv3hr4z6uq6mhe5l5v`            | `0x742d35Cc6634C0532925a3b844Bc454e4438f44e` |
| 长度     | 45 个字符左右                                              | 42 个字符                                    |
| 前缀     | 人类可读前缀（Bech32，如 `cosmos1`, `evmos1`, `osmo1` 等） | 固定前缀 `0x`                                |
| 编码方式 | **Bech32** 编码（Base32 + 校验码）                         | **十六进制** 编码（Base16）                  |

### Cosmos 地址（Tendermint / Cosmos SDK 系列）

1. **密钥算法**：
    默认使用 **secp256k1** 椭圆曲线（与以太坊相同）。

2. **公钥哈希**：

   - 对公钥执行 `SHA-256` → `RIPEMD-160`，得到 20 字节哈希。先用 **SHA-256** 算法对公钥进行哈希输出 256 位（32 字节）哈希，再把结果用 **RIPEMD-160** 再次哈希输出 160 位（20 字节）哈希。

   - **两者结合的好处：**

     - 双重哈希增加安全性（即使其中一种算法被部分破解，组合仍安全）。
     - 输出变短，方便展示（20 字节 → 40 字符左右的十六进制字符串）。
     - 比直接用公钥或单哈希更抗碰撞和抗彩虹表攻击。

   - 即：

     ```
     address = RIPEMD160(SHA256(pubkey))
     ```

3. **Bech32 编码**：

   - 把哈希结果用 Bech32 编码并加上链前缀。
   - 例如：
     - Cosmos Hub → `cosmos1...`
     - Evmos → `evmos1...`
     - Osmosis → `osmo1...`

> Cosmos 地址实际上是公钥哈希值的 Bech32 表达形式，与比特币的地址生成机制相似。
