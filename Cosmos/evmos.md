# EVMOS

## 一、地址格式对比

| 项目     | Cosmos 地址                                                | 以太坊地址                                   |
| -------- | ---------------------------------------------------------- | -------------------------------------------- |
| 示例     | `cosmos1p9h8f9q0u5a0eh5sgkx6jv3hr4z6uq6mhe5l5v`            | `0x742d35Cc6634C0532925a3b844Bc454e4438f44e` |
| 长度     | 45 个字符左右                                              | 42 个字符                                    |
| 前缀     | 人类可读前缀（Bech32，如 `cosmos1`, `evmos1`, `osmo1` 等） | 固定前缀 `0x`                                |
| 编码方式 | **Bech32** 编码（Base32 + 校验码）                         | **十六进制** 编码（Base16）                  |

### Cosmos 地址（Tendermint / Cosmos SDK 系列）

1. **密钥算法**：
    默认使用 **secp256k1** 椭圆曲线（与以太坊相同）。

2. **公钥哈希**：

   - 对公钥执行 `SHA-256` → `RIPEMD-160`，得到 20 字节哈希。先用 **SHA-256** 算法对公钥进行哈希输出 256 位（32 字节）哈希，再把结果用 **RIPEMD-160** 再次哈希输出 160 位（20 字节）哈希。

   - **两者结合的好处：**

     - 双重哈希增加安全性（即使其中一种算法被部分破解，组合仍安全）。
     - 输出变短，方便展示（20 字节 → 40 字符左右的十六进制字符串）。
     - 比直接用公钥或单哈希更抗碰撞和抗彩虹表攻击。

   - 即：

     ```
     address = RIPEMD160(SHA256(pubkey))
     ```

3. **Bech32 编码**：

   - 把哈希结果用 Bech32 编码并加上链前缀。
   - 例如：
     - Cosmos Hub → `cosmos1...`
     - Evmos → `evmos1...`
     - Osmosis → `osmo1...`

> Cosmos 地址实际上是公钥哈希值的 Bech32 表达形式，与比特币的地址生成机制相似。



# 配置说明

### 节点启动前需要的配置：

`genesis.json`  创世配置，决定链的初始状态

`config.toml`  Tendermint 层配置（网络 + 共识），控制共识层和网络通信

`app.toml`  应用层配置



### 一、`genesis.json`

`genesis.json` 定义了区块链网络启动时的所有状态。
 所有节点必须使用**完全一致**的 genesis 文件，否则无法共识。

### 关键字段说明：

| 字段                                | 说明                                                         |
| ----------------------------------- | ------------------------------------------------------------ |
| `chain_id`                          | 网络标识符，例如主网为 `evmos_9001-2`，用于防止不同网络间混淆。 |
| `genesis_time`                      | 创世块的时间戳，决定网络启动时间。                           |
| `validators`                        | 初始验证人列表，每个验证人包含公钥、公有地址和权重（投票权重）。 |
| `app_state`                         | 定义链上模块的初始状态（账户余额、staking、治理、EVM 配置等）。 |
| `app_state.auth.accounts`           | 创世账户及其初始余额。                                       |
| `app_state.bank.balances`           | 每个账户的代币持有量。                                       |
| `app_state.staking.params`          | Staking 模块参数，如最小质押量、解绑周期。                   |
| `app_state.gov.voting_params`       | 治理模块参数，如投票期长度。                                 |
| `app_state.evm.params.chain_config` | EVM 兼容配置，例如启用的以太坊改进提案（EIP）。              |
| `consensus_params`                  | 共识规则，如每个区块的最大 gas、最大交易数。                 |



### 二、`config.toml`

主要控制节点如何参与网络、共识与日志。

### 核心配置项：

#### P2P网络连接

| 参数               | 示例                                            | 说明                                 |
| ------------------ | ----------------------------------------------- | ------------------------------------ |
| `moniker`          | `"my-node"`                                     | 节点名称，会在 P2P 网络中显示。      |
| `seeds`            | `"node1.evmos.org:26656,node2.evmos.org:26656"` | 初始种子节点地址列表，用于节点发现。 |
| `persistent_peers` | `"id@ip:26656"`                                 | 永久连接的节点，保证长期通信。       |
| `external_address` | `"tcp://203.0.113.12:26656"`                    | 节点公网地址，用于让其他节点连接你。 |
| `pex`              | `true`                                          | 是否启用节点发现（Peer Exchange）。  |

#### RPC / API / Prometheus

| 参数                         | 示例                    | 说明                       |
| ---------------------------- | ----------------------- | -------------------------- |
| `laddr`                      | `"tcp://0.0.0.0:26657"` | P2P网络的RPC监听地址。     |
| `rpc.cors_allowed_origins`   | `["*"]`                 | 允许跨域请求的来源。       |
| `instrumentation.prometheus` | `true`                  | 开启 Prometheus 指标采集。 |

#### 共识与区块

| 参数                  | 示例    | 说明                               |
| --------------------- | ------- | ---------------------------------- |
| `timeout_commit`      | `"5s"`  | 共识提交的超时时间，影响出块时间。 |
| `skip_timeout_commit` | `false` | 是否跳过共识等待（通常不建议）。   |
| `create_empty_blocks` | `true`  | 是否在无交易时出空块。             |



### 三、`app.toml` — 应用层配置

主要定义 RPC、REST、EVM、治理、gas、快照等应用层参数。

### 核心配置项：

#### 服务接口

| 参数           | 示例                   | 说明                |
| -------------- | ---------------------- | ------------------- |
| `api.enable`   | `true`                 | 启用 REST API。     |
| `api.address`  | `"tcp://0.0.0.0:1317"` | REST API 监听地址。 |
| `grpc.enable`  | `true`                 | 启用 gRPC 服务。    |
| `grpc.address` | `"0.0.0.0:9090"`       | gRPC 监听端口。     |

#### EVM / JSON-RPC

| 参数               | 示例                            | 说明                             |
| ------------------ | ------------------------------- | -------------------------------- |
| `json-rpc.enable`  | `true`                          | 启用以太坊兼容的 JSON-RPC 服务。 |
| `json-rpc.address` | `"0.0.0.0:8545"`                | JSON-RPC 监听地址。              |
| `json-rpc.api`     | `["eth","net","web3","txpool"]` | 启用的 JSON-RPC 模块列表。       |
| `evm.tracer`       | `"json"`                        | 交易调试输出格式。               |

#### Gas 与经济模型

| 参数                 | 示例                            | 说明                          |
| -------------------- | ------------------------------- | ----------------------------- |
| `minimum-gas-prices` | `"0.025aevmos"`                 | 节点接受交易的最低 gas 价格。 |
| `index-events`       | `["tx.hash", "message.action"]` | 事件索引字段，用于查询。      |

#### 状态同步 / 快照

| 参数                              | 示例   | 说明                       |
| --------------------------------- | ------ | -------------------------- |
| `state-sync.snapshot-interval`    | `1000` | 每隔多少区块生成一次快照。 |
| `state-sync.snapshot-keep-recent` | `2`    | 保留的快照数量。           |





### 节点运行后的配置项：

重启节点生效：节点本地参数，不影响共识的配置项

治理投票：链上治理（Governance）机制 能够修改的参数化模块配置项

硬分叉：涉及 **共识兼容性**，需要共识分叉修改



### 重启修改

### `genesis.json`（创世配置）不可修改

该文件在链启动后几乎**禁止自行修改**。因为它定义了共识初始状态，自行修改会破坏共识。



### `config.toml`（Tendermint 层配置）可修改（重启后生效）的常见参数：

| 参数                         | 说明                                | 修改影响                           |
| ---------------------------- | ----------------------------------- | ---------------------------------- |
| `moniker`                    | 节点名称（显示在 P2P 网络中）       | 无共识影响，可自由改。             |
| `log_level`                  | 日志级别 (`info`, `debug`, `error`) | 可调节日志详细度。                 |
| `laddr`                      | RPC 服务地址                        | 仅本地接口变动，需重启。           |
| `external_address`           | 公网 P2P 地址                       | 修改后节点将以新地址广播。         |
| `seeds` / `persistent_peers` | 连接的节点列表                      | 修改后重启生效，用于更换对等节点。 |
| `pex`                        | 启用/禁用节点发现                   | 可更改网络行为。                   |
| `instrumentation.prometheus` | 开启/关闭监控接口                   | 重启后生效。                       |



### `app.toml`（应用层配置）可修改（重启后生效）的参数：

| 参数                                  | 说明                      | 修改影响                 |
| ------------------------------------- | ------------------------- | ------------------------ |
| `api.enable` / `grpc.enable`          | 启用 REST / gRPC          | 控制接口是否开放。       |
| `api.address`, `grpc.address`         | 修改监听端口或 IP         | 影响 API 访问。          |
| `json-rpc.enable`, `json-rpc.address` | 启用 EVM JSON-RPC         | 用于以太坊兼容服务。     |
| `json-rpc.api`                        | 控制暴露的 RPC 模块       | 可节省资源或增强安全性。 |
| `minimum-gas-prices`                  | 节点接受交易的最低 Gas 价 | 动态调整经济门槛。       |
| `telemetry.enabled`                   | 启用监控                  | 重启后生效。             |
| `state-sync.snapshot-interval`        | 快照生成频率              | 用于状态同步优化。       |



### 治理修改

**质押与验证人**

| 参数                  | 作用                       |
| --------------------- | -------------------------- |
| `unbonding_time`      | 解除质押锁定期             |
| `max_validators`      | 最大验证人数量             |
| `max_entries`         | 每个验证人最大解质押条目数 |
| `min_commission_rate` | 最低佣金比率               |
|                       |                            |

**惩罚机制**

| 参数                     | 作用             |
| ------------------------ | ---------------- |
| `signed_blocks_window`   | 掉线惩罚评估周期 |
| `min_signed_per_window`  | 掉线容忍率       |
| `downtime_jail_duration` | 监禁期           |

**治理自身规则**

| 参数             | 作用               |
| ---------------- | ------------------ |
| `voting_period`  | 投票期长度         |
| `min_deposit`    | 提案最小抵押       |
| `quorum`         | 投票最低参与率     |
| `threshold`      | 通过提案的票数比例 |
| `veto_threshold` | 否决比例           |

**通胀模型**

| 参数                    | 作用           |
| ----------------------- | -------------- |
| `inflation_rate_change` | 通胀率变化速度 |
| `inflation_max`         | 通胀率上限     |
| `inflation_min`         | 通胀率下限     |
| `goal_bonded`           | 目标质押率     |

**奖励分配**

| 参数                    | 作用                     |
| ----------------------- | ------------------------ |
| `base_proposer_reward`  | 基础提议奖励             |
| `bonus_proposer_reward` | 额外奖励                 |
| `withdraw_addr_enabled` | 是否允许更改奖励提取地址 |



### 硬分叉

| 参数                   | 修改效果                                  |
| ---------------------- | ----------------------------------------- |
| `chain_id`             | 改变网络 ID                               |
| `genesis_time`         | 重新定义创世时间                          |
| `version.consensus`    | 升级共识协议                              |
| `pub_key_types`        | 更改签名算法                              |
| `time_iota_ms`         | 调整出块最小间隔                          |
| `chain_config`（EIPs） | 启用新的以太坊升级（如 London, Shanghai） |
| 模块启用/禁用          | 启用动态费市场                            |
| 模块新增 / 删除        | 改变 SDK 模块结构                         |
| 交易签名验证逻辑       | 改动编码规则                              |
| store key / db 结构    | 改变状态树结构                            |
