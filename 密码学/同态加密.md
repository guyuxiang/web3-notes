# 同态加密

数据加密后，仍然可以直接拿来计算；算完再解密，结果和“先明文计算、再加密”一致。

- 先加密：`Enc(m1), Enc(m2)`
- 在密文上计算：`Eval(f, Enc(m1), Enc(m2))`
- 解密后得到：`Dec(...) = f(m1, m2)`

也就是：

> **Dec(Eval(f, Enc(m))) = f(m)**

这就是“同态”的意思：
 **密文空间上的运算，映射到明文空间的对应运算。**



## 从最简单的例子理解“同态”

先别上来就看 FHE，先看一个“玩具版”例子。

假设有一种很简单的“加密”：

- 明文是 `m`
- 密钥是 `k`
- 加密：`Enc(m) = m + k`

那么两个密文相加：

- `Enc(m1) + Enc(m2) = (m1 + k) + (m2 + k) = m1 + m2 + 2k`

如果你设计一个对应的“解密规则”，能把这个结果还原成 `m1 + m2`，那这就具有某种**加法同态**。



## 同态加密分哪几类

### PHE：部分同态加密

只支持一种运算，通常是：

- 只支持加法
   或
- 只支持乘法

经典例子：

- **RSA**：有某种乘法同态性质
- **Paillier**：有加法同态性质

也就是说它能很适合做：

- 安全求和
- 电子投票统计
- 隐私聚合

但它不能随便做任意程序。

### SHE：有限同态加密

可以支持：

- 加法
- 乘法

但只能支持**有限次数**的乘法。

因为每做一次运算，密文里的“噪声”都会增长；
 噪声太大，最后就没法正确解密了。

### FHE：全同态加密

FHE = **Fully Homomorphic Encryption**

它支持：

- 任意次加法
- 任意次乘法
- 因此理论上可以表示**任意可计算函数**

因为电路里只要有：

- AND / XOR
   或者
- 加法 / 乘法

就能表达通用计算。
