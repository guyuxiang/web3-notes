## Zcash

**Zcash** 是一个主打“隐私保护”的区块链，于 2016 年推出，源自比特币代码，继承了 UTXO 模型，但加入了更强的匿名技术。

Zcash 的关键技术是：

👉 零知识证明（Zero-Knowledge Proof）

更具体地说，它使用一种叫 **zk-SNARKs** 的算法。

Zcash 提供两种交易模式：

1. 透明地址（t-address）
   - 类似比特币
   - 所有交易公开
2. 隐私地址（z-address）
   - 完全加密
   - 外界看不到任何交易细节

# 混币器（Mixers）

### 核心原理

- 用户把钱存进一个池子
- 之后从另一个地址提取
- 利用零知识证明证明“你有权取钱”，但不暴露来源

👉 本质：**打断“输入地址 → 输出地址”的链路**

### 代表项目

### 1. Tornado Cash

- 基于 zk-SNARK 的混币器 
- 存入和取出地址完全断开关联 

👉 优点：

- 匿名性强（匿名集越大越好）

👉 缺点：

- 只能做“转账”，不能做 DeFi
- 被监管重点关注 

------

### 2. Railgun

类似 Tornado Cash（隐私池） + （UTXO模型） + zk-SNARK 实现了隐私



#### 核心结构：UTXO（Note 模型）

Railgun 不用账户余额，而是：

👉 用 **“notes（票据）”表示资产**

每个 note 包含：

- token 类型（例如 USDC）
- 数量（加密）
- 拥有者公钥（加密）
- 随机数（防重放）

假设 A → B 转账：

### 步骤：

#### 存款（进入隐私层）

用户调用：

```
deposit(USDC)
```

1. 用户把 USDC 转给 Railgun 合约
2. 同时生成一个 encrypted note
3. note 加入 Merkle Tree



#### 隐私转账

- 消耗旧 notes

- 生成新 notes（给 B）

- 生成 zk 证明：

  证明：

  - 我有这些钱
  - 没有双花
  - 输入 = 输出

用户在本地：

1. 选择 notes

2. 构造交易

3. 生成 zk proof

提交：

```
transact(proof, commitments)
```



####  提现（退出隐私层）

- 智能合约验证 zk proof
- 更新 Merkle Tree

👉 链上只看到：

- proof
- commitment（哈希）
- ❌ 看不到金额 / 地址



### 提现（退出隐私层）

用户：

```
withdraw()
```

- 销毁 note
- 从合约取出 USDC



#### Merkle Tree（关键）

Railgun 合约维护一个：

👉 **所有 notes 的 Merkle Tree**

作用：

- 证明某个 note 存在（inclusion proof）
- 防止 double spend（nullifier）



#### 双花防护（Nullifier）

每个 note 在花掉时会生成：

👉 **nullifier（唯一标识）**

- 一旦用过，就不能再用
- 合约会记录它





### 3. Privacy Pools（合规）

- 类似 Tornado，但加入**合规证明**
- 可以证明“资金不是来自黑名单”

👉 方向：**“隐私 + 合规”**



# ZK隐私Layer

代表：**Aztec** 2025 已主网上线 L2

### 核心原理

- 用零知识证明隐藏：
  - 余额
  - 转账金额
  - 地址关系
- 同时还能执行智能合约

👉 本质：**在链上构建“私有状态”**

------

### 1. Aztec Network

- zk-rollup 隐私 L2 
- 支持：
  - 私密账户
  - 私密 DeFi

👉 特点：

- 不只是转账，而是**“私密智能合约”**
- 未来方向：隐私版 Ethereum



# 隐身地址（Stealth Addresses）

代表：Vitalik 推的方向，一次性地址（one-time address）

### 核心原理

- 每次收款生成一个新地址
- 外界无法关联收款人

👉 类似：

- 银行账户 vs 每次收款新账户

📌 特点：

- 不隐藏金额
- 但隐藏“谁收钱”
